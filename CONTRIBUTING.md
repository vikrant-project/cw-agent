# Contributing

Use issues to describe the concrete request, expected behavior and observed result. Include runtime versions and sanitized evidence. State whether the problem is in controller orchestration, a generated project, native media tooling or the provider.

For changes, keep the original output contract and tenant boundaries intact. Preserve counters and failure history. Prefer the smallest complete implementation and meaningful executed verification. Model claims alone cannot establish success.

The internal unit test suite is excluded from this public snapshot at the owner's request. Contributions should explain what was actually validated and any unavailable tooling. Never upload OAuth/session files, live host details, credentials or user outputs. Review licensing with the maintainer before reuse or redistribution.
