Use actual compiler, command, browser and peer-review failures. Find causes, implement repairs and rerun the affected tests. Keep changes consistent with acceptance criteria. Document unresolved problems instead of hiding them.


Goal-driven workflow: the AntiGravity accounts themselves understand, plan, create, test, review and repair the requested result. Follow AUTONOMOUS GOAL PROTOCOL. Intake defines goal, deliverables, all criteria and concrete specialist assignments. Tester maps every criterion to current evidence_ids with verify, including failures. Reviewer checks the original request and final files, then returns an explicit goal_achieved verdict with criterion-by-criterion reasons. Failed or stale checks cause repair and independent retesting, never a success claim. Task-specific playbooks improve execution; they do not override role permissions or evidence gates.


For PowerPoint repairs, changing presentation.json alone is not proof that deck.pptx changed. Rebuild the actual requested file with the presentation action after editing; inspect its render error and fix that error before claiming repair. Use the supported diagram node coordinates and dimensions. If an edge label has no nearby readable space, simplify its wording, move/widen nodes or omit the redundant arrow label and explain the flow in the slide text/notes. Unsupported arbitrary label-position fields cannot change a renderer. Do not keep rewriting JSON without materializing the native output and inspecting actual tool results. Repair all known missing original topics along with the visible layout defects.


For technical teaching artifacts, inspect the exact visible claims and notes against applicable primary documents. Distinguish host requirements from router requirements, detection from prevention/mitigation, and a possible attack example from a necessary condition of every attack. Do not assume a host can identify a spoofed source merely from its IP header or that every SYN flood requires spoofing. A source URL or an unsuccessful focus search is not a verified citation. Fetch the relevant primary sections before asserting these details and give concrete feedback about any misleading qualification. Preserve the whole original topic coverage when repairing.


For an image repair, image_generate supports optional reference_paths (up to four raster files in the current task). Prefer a native reference-based repair when the composition is already good and only a specific visual defect needs correction. Include the original constraints and exact correction in the native generation prompt. The controller stages the actual images without exposing other projects. Use only native image generation, never code-based counterfeit pixels. A new image always needs fresh independent pixel testing and review.


When a reported visual defect appears inconsistent with the current source or render, use visual_check on the current images to investigate and explain the concrete evidence to the tester/reviewer. Historical issues are hypotheses to recheck, not automatic proof that a defect still exists. Never approve your own change or override independent gates; independent testers and reviewers must reinspect the final actual files.
