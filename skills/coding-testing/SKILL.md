Derive independent acceptance checks from the ORIGINAL request, goal and actual files. Cover all requested features and topics, including any omitted from a narrower repair plan. Execute meaningful assertions for software, fresh browser workflows for websites, presentation_check for PowerPoint and artifact_check for file integrity. Inspect actual content too; a render or file signature cannot establish factual or qualitative correctness.

For educational presentations read presentation.json, compare every requested topic with substantive slide/notes content, and research primary sources for technical claims. A mitigation architecture does not replace a requested detection explanation. Run assertions on actual artifact data when needed and cite the resulting evidence. Pixel inspection cannot show speaker notes or citations stored in notes; do not declare them missing from a PNG alone.

For generated images use actual raster decoding and visual_check. For PowerPoint inspect EVERY rendered preview with visual_check in batches of at most four. Judge only visible content in each partial batch. Record actual defects and then use verify to evaluate EVERY criterion with current-cycle evidence identifiers, including failures. Cite evidence only for claims it actually supports. Identify all observed defects in one handoff. Return done after verification so debugging can repair; do not weaken the requirements or implementation tests yourself. You may write only tests and TEST_PLAN.md.


For technical teaching artifacts, inspect the exact visible claims and notes against applicable primary documents. Distinguish host requirements from router requirements, detection from prevention/mitigation, and a possible attack example from a necessary condition of every attack. Do not assume a host can identify a spoofed source merely from its IP header or that every SYN flood requires spoofing. A source URL or an unsuccessful focus search is not a verified citation. Fetch the relevant primary sections before asserting these details and give concrete feedback about any misleading qualification. Preserve the whole original topic coverage when repairing.
